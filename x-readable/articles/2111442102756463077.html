收款前让 Opus 检查这 23 项支付与安全清单

Claude Code tip: before your vibe-coded app takes its first payment, have Opus 5.5 check 𝘁𝗵𝗲𝘀𝗲 𝟮𝟯 𝘁𝗵𝗶𝗻𝗴𝘀:

Claude Code 技巧：在 vibe-coded 应用收第一笔款前，让 Opus 5.5 检查这 23 项：

> One design doc that every color, font size and spacing follows

> 一份设计文档，约束所有颜色、字号、间距

> A real screen for every state: loading, empty, error

> 每种状态都有真实页面：加载、空态、错误

> Private keys only on the server, with your frontend files and git history searched, and anything that ever leaked replaced

> 私钥只在服务端；搜过前端文件和 git 历史，泄露过的一律轮换

> Every endpoint checks login and permissions on the server, and RLS is on in the database

> 每个接口在服务端校验登录与权限，数据库开了 RLS

> Spending caps or alerts on anything billed per use: AI, SMS, email

> 按量计费的东西设消费上限或告警：AI、短信、邮件

> Payment webhooks verify their signature, and the same payment sent twice only counts once

> 支付 webhook 验签；同一笔支付重放只计一次

> Refunds, cancellations and failed charges each run once in test mode, ending in the right status

> 退款、取消、扣款失败在测试模式各跑通一次，状态正确

> Access revoked on time when a trial or subscription ends

> 试用或订阅结束时及时收回访问

> When payments switch from test to live, the live keys and webhook signing secret are set up again

> 从测试切到线上时，重新配置线上密钥和 webhook 签名密钥

> Money stored as integers in the smallest currency unit, like Stripe does. No floats: in JS, 0.1 + 0.2 isn't 0.3

> 金额用最小货币单位整数存，像 Stripe。别用浮点：JS 里 0.1+0.2≠0.3

> A user double-clicking submit creates only one order

> 用户双击提交只创建一笔订单

> Sales tax or VAT set up for the countries you sell to

> 为销售国家配好销售税/增值税

> Your terms and privacy policy match what the code actually does

> 条款与隐私政策与代码实际行为一致

> Daily automatic backups (Supabase's free plan has none, so upgrade to Pro or schedule your own dump), plus one test restore into a new database

> 每日自动备份（Supabase 免费版没有，升 Pro 或自建 dump），并做过一次恢复到新库的演练

> Every schema migration has its reverse SQL written and has been run both ways on a copy of production data

> 每次 schema 迁移都有反向 SQL，并在生产数据副本上正反跑过

> Lists over 1,000 rows aren't silently cut off. Supabase's API returns at most 1,000 rows by default

> 超过 1000 行的列表不会被静默截断。Supabase API 默认最多返回 1000 行

> Times stored as timestamptz, with each user's timezone in its own column, so reminders go out in their local time

> 时间存 timestamptz，用户时区单独一列，提醒按本地时间发出

> Soft delete first, with RLS hiding deleted rows too. When a user deletes their account, wipe it for real

> 先软删，RLS 也隐藏已删行。用户删账号时再真正擦除

> Users can export their own data

> 用户可导出自己的数据

> Names with apostrophes, emoji or right-to-left text don't break any input

> 含撇号、emoji 或从右到左文字的名字不会弄坏输入

> Images in WebP or AVIF, with anything below the fold loading as you scroll

> 图片用 WebP 或 AVIF，折线以下滚动加载

> Indexes on the fields you filter by most. With a few dozen test rows everything is fast; real data is where it slows down

> 常过滤字段有索引。几十行测试数据都很快；真实数据才会慢

> Error monitoring hooked up, so you're the first to know when something breaks

> 接好错误监控，出问题你第一个知道

Send this whole list to Claude Code and add this line at the end. It checks every item and gives you a table 👇

把整份清单发给 Claude Code，末尾加这句。它会逐项检查并给你表格 👇

"Split it across 5 subagents: design and speed, security, payments, data, and after launch. Check without editing anything, and for each item note pass or fail and which file the problem is in. For anything only visible in a dashboard, mark it 'needs my confirmation' and give me the steps to look. Only test backups and restores on a test database, only test payments in test mode, and don't touch production data. Show me the table first, and don't fix anything until I confirm."

「拆成 5 个子代理：设计与速度、安全、支付、数据、上线后。只检查不改；每项标 pass/fail 以及问题所在文件。只能在仪表盘看到的标「需我确认」。」
