跑十几个 Agent 后，我们如何把 Lint/CI 提速数十倍

作者：@PaulSangleF（Paul）
原文：https://x.com/PaulSangleF/status/2107465723513561197

we merged 4x more commits last week than we did a month ago (thanks opus 5.5). our dev setup and CI couldn't keep up, so we reworked both:

上周合并的 commit 是一个月前的 4 倍（多亏 Opus 5.5）。本地开发和 CI 跟不上，于是两边都重做了：

・ lint: 4x faster

lint：快 4 倍

・ memory per agent session: half

每个 agent 会话内存：减半

・ CI setup step: 50x faster

CI setup 步骤：快 50 倍

・ CI type check: 10x faster

CI 类型检查：快 10 倍

we often run 10+ agents at once locally, and each one runs its own lint, type checks and tests.

我们经常本地同时跑 10+ 个 agent，每个各自跑 lint、类型检查和测试。

from time to time, several agents would run these at the same time and block each other.

偶尔几个 agent 会同时跑这些检查，互相卡住。

a 64 GB MBP would run out of memory and crash. so most of the work was making things faster and lighter, or getting rid of them

64 GB 的 MBP 会内存耗尽崩溃。所以大部分工作是让检查更快更轻，或干脆去掉。

we revamped our local setup to make checks faster and use less memory:

我们重做了本地环境，让检查更快、更省内存：

・ oxlint and oxfmt instead of eslint and prettier, and type-aware lint only runs in CI. linting a changed file went from over 10s to a few seconds

用 oxlint 和 oxfmt 替代 eslint 和 prettier，感知类型的 lint 只在 CI 跑。改动文件的 lint 从超过 10 秒降到几秒

・ a hook formats every file an agent edits, so agents don't have to take a turn to format it

用 hook 格式化 agent 编辑的每个文件，agent 不必再花一轮去格式化

・ typescript 7's native LSP instead of tsserver. each agent session uses about half the memory

用 TypeScript 7 原生 LSP 替代 tsserver。每个 agent 会话大约只用一半内存

・ agents run one check script after each change. it installs missing packages and env files first, then lints, type-checks and runs the tests for what changed

每次改动后 agent 跑一个检查脚本：先装缺的包和环境文件，再 lint、类型检查、跑相关测试

・ only 3 type checks or big test runs can run at once across all worktrees, so they don't slow each other down

所有 worktree 同时最多 3 个类型检查或大测试，避免互相拖慢

we revamped our CI to make it faster:

我们重做了 CI 让它更快：

・ every CI job installs pnpm before it can install our packages. the standard github action for this (pnpm/action-setup) installs pnpm through npm, and that hung for 3-7 min on most of our test jobs. we now download the pnpm binary from github releases, which takes about 4s

每个 CI job 装包前要先装 pnpm。官方 action（pnpm/action-setup）经 npm 装 pnpm，多数测试 job 会卡 3–7 分钟。我们改为从 GitHub releases 下 pnpm 二进制，大约 4 秒

・ our type check needs about 9.5 GB of memory. github's standard runners have 8 GB, so it ran out of memory and took 206s. on a 16 GB machine it takes 20s

类型检查大约要 9.5 GB 内存。GitHub 标准 runner 只有 8 GB，会 OOM，花 206 秒；16 GB 机器只要 20 秒

・ vercel builds type-check with typescript 7 (85s to 45s), and previews only build for PRs that change the database

Vercel 构建用 TypeScript 7 做类型检查（85s→45s），且只有改数据库的 PR 才构建预览

if you're running lots of agents, look at what they're waiting on. for us it was mostly lint, type checks and CI setup

如果你跑很多 agent，看看它们在等什么。对我们来说主要是 lint、类型检查和 CI setup
