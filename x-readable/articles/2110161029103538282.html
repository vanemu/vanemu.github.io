Codex 占盘太大？3 招把会话从 60GB+ 降到 30GB

作者：@miu21590（vechen）
原文：https://x.com/miu21590/status/2110161029103538282

Tibo finally acknowledged that Codex eats way too much disk space.

Tibo 终于承认 Codex 太吃磁盘了。

My Codex sessions went from 60+ GB to 30 GB using just 3 tricks. Guess it's time to share them.

我的 Codex 会话从 60+ GB 降到 30 GB，只用了 3 招。该分享了。

・ Delete subagent sessions

删除子代理会话

Codex stores subagent sessions that don't even appear in your sidebar. Some of mine were over 2 GB EACH.

Codex 会存侧边栏都看不到的子代理会话。我有些单个就超过 2 GB。

Ask Codex to delete inactive subagent sessions or those unused for 48+ hours.

让 Codex 删除不活跃或超过 48 小时未用的子代理会话。

・ Remove embedded images from sessions

去掉会话里的嵌入图片

Some images take 1–2 MB each and get duplicated hundreds of times inside session files.

有些图每张 1–2 MB，在会话文件里被复制成百上千次。

Ask Codex to replace embedded images with tiny 1×1 pixel placeholders while preserving the session structure.

让 Codex 把嵌入图换成 1×1 像素占位，同时保留会话结构。

・ Reclaim unused SQLite space

回收未用的 SQLite 空间

Codex's SQLite database can accumulate gigabytes of unused pages (freelist). In my case, sometimes 1–3 GB.

Codex 的 SQLite 会堆积数 GB 未用页（freelist）。我这边有时 1–3 GB。

Ask Codex to check the freelist and prepare VACUUM commands to reclaim that space after Codex is completely closed.

让 Codex 检查 freelist，并在完全退出 Codex 后准备 VACUUM 命令回收空间。

Exact prompts (from reply)

精确提示词（来自回复）

・ Delete hidden subagent sessions

删除隐藏的子代理会话

Find my local Codex session storage and identify all subagent sessions inactive for 48+ hours. Safely delete them without breaking parent sessions.

找到本地 Codex 会话存储，识别所有超过 48 小时不活跃的子代理会话。安全删除，不破坏父会话。

・ Replace embedded images

替换嵌入图片

Scan all my Codex sessions and calculate what percentage of them is occupied by embedded images. Replace images from before each session's most recent context compaction with valid 1×1 pixel placeholders.

扫描所有 Codex 会话，计算嵌入图占比。把每次上下文压缩之前的图片换成合法的 1×1 像素占位。

・ Reclaim SQLite space

回收 SQLite 空间

Find my local Codex SQLite database and check how much space is wasted on unused pages (freelist). Calculate the reclaimable size and prepare safe VACUUM commands to run after Codex is completely closed. Don't modify anything yet.

找到本地 Codex SQLite 数据库，检查 freelist 浪费了多少空间。计算可回收大小，准备在完全关闭 Codex 后安全执行的 VACUUM 命令。先别改任何东西。
